Security

Last updated: December 2024

DRAFT: This Security page is a placeholder and is subject to change. Please review it carefully and contact us if you have any questions.

1. Reporting Security Vulnerabilities

If you discover a security vulnerability in doctorhide, please email us at security@doctorhide.com with details of the vulnerability. Please do not publicly disclose the vulnerability until we have had a reasonable opportunity to address it.

2. Encryption

doctorhide uses industry-standard encryption to protect your data in transit and at rest. All communications between your browser and our servers are encrypted using TLS/SSL.

3. Authentication

We require all users to authenticate with a strong password and two-factor authentication (2FA) via a time-based one-time password (TOTP) application. Backup codes are provided for account recovery.

4. Access Controls

Access to doctorhide is controlled through authentication and authorization mechanisms. Only authenticated users can access their secrets, and access is further restricted based on organization and project permissions.

5. Audit Logging

doctorhide maintains audit logs of all access to secrets and administrative actions. These logs are retained for security and compliance purposes.

6. Data Protection

Your secrets are encrypted using PBKDF2 with Fernet. Even in the event of a database breach, secrets cannot be decrypted without the proper encryption keys.

7. Infrastructure Security

doctorhide infrastructure is designed with security as a core principle. We implement regular security updates, monitoring, and incident response procedures.

8. Security Practices

We follow industry-standard security practices including:

  • Regular security audits and penetration testing
  • Secure coding practices
  • Principle of least privilege
  • Defense in depth
  • Incident response procedures

9. Contact

For security inquiries, please contact security@doctorhide.com. For other inquiries, visit our website or contact us through the support channels.
